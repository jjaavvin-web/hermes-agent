## Problem

P4 (PR #42) shipped the codex sessions REST API and P4.1 (PR #47)
shipped the SSE event stream — but no dashboard surface to consume
them.  Operators can only see codex session state by querying the
JSON file by hand or by reading dispatcher logs.  A live tab in the
existing dashboard SPA closes the loop.

## Goal

After this ISA:

- `web/src/pages/CodexSessionsPage.tsx` renders one card per tracked
  codex session: state badge, sid, ISA id + phase, PR # + state + URL,
  merge label, review iteration count, worktree liveness, Discord
  thread deep-link, last activity timestamp.
- The page fetches `/api/dashboard/codex-sessions` once on mount and
  subscribes to `/api/pulse/stream` for live `codex.session` events.
  Any event triggers a snapshot refetch (cheap; avoids field-level
  patching drift).
- `App.tsx` registers `/codex-sessions` in
  `BUILTIN_ROUTES_CORE` + adds a `GitBranch`-icon nav item after the
  Hives tab.
- `hermes_cli/dashboard_codex_sessions.py` snapshot endpoint now
  surfaces the P3.5 PR meta fields (`pr_number`, `pr_url`, `pr_state`,
  `head_branch`, `merge_label`, `merge_requested_at`, `merged_at`,
  `merge_commit_oid`, `closed_at`) — without these the SPA tab
  cannot render PR links.

## Out of Scope

- Optimistic UI updates on operator actions (pause/resume/kill/
  force-merge from the tab itself).  Tombstoned: the existing
  destructive routes need confirm-token UX (P4 dashboard tab follow-up).
- Field-level patching from SSE events (avoid full snapshot refetch).
  YAGNI for first ship.
- ISA verbatim viewer / log tail inline in the card (P4 follow-up).
- Slash `/status` deep-link from Discord to a specific session's
  card on the SPA tab (P4 follow-up).

## Constraints

- **No coupling to dispatcher internals.**  The tab reads only the
  dashboard REST + SSE endpoints — no imports of `gateway/*` modules.
- **Forgiving SSE.**  Connection drops trigger an auto-reconnect
  with a 3 s delay (matches `PulseTranscript`'s pattern).  Malformed
  payloads are silently ignored.
- **No dist commits.**  `hermes_cli/web_dist/` is gitignored
  per top-level `.gitignore` — the PR ships source only.  Operator
  / CI runs `npm run build` post-merge.

## Decisions

**D-1 (2026-05-25): refetch snapshot on every SSE event.**
Field-level patching from event payloads would couple the SPA to
the exact event shape and risk drift.  A snapshot refetch on each
event is cheap (~50 ms) and keeps the tab a pure consumer of the
REST snapshot.  Optimize only if event rates grow past one per
second per session.

**D-2 (2026-05-25): source-only PR; no web_dist commit.**
`hermes_cli/web_dist/` is gitignored.  CI / operator runs
`npm run build` post-merge to regenerate the dashboard bundle.
The few tracked legacy files in `web_dist/` are noise — left as-is
to avoid a destructive cleanup riding on a feature PR.

**D-3 (2026-05-25): no optimistic UI for destructive operations.**
P4's destructive routes (kill / force-merge) require confirm tokens.
Building the operator-confirmation modal is a separate UX
exercise — tombstoned.  This PR ships the read-only surface.

## Changelog

2026-05-25 — P4 + P4.1 shipped data layers, P4.2 wires the UI
  conjectured:   the SPA could pull only from /api/dashboard/codex-sessions
                 with periodic polling — no SSE needed
  refuted by:    P4.1's SSE iter was already in flight and the cost
                 of subscribing was tiny (one EventSource).  Polling
                 alone would leave the tab feeling dead between
                 polls, which mattered for the MERGING→COMPLETE
                 transition that fires asynchronously
  learned:       when a data layer ships SSE, the UI layer should
                 consume it on day 1.  The marginal cost is small;
                 the UX gain (live updates) is large
  criterion now: ISC-3 + ISC-4 — initial fetch + SSE subscription
                 + refetch on event

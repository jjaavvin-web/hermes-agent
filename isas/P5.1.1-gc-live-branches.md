## Problem

P5.1 shipped the hourly gc tick passing only ``tracked_sids`` to
``broker.gc()``.  The watcher's own design (P5.1 D-2) flagged
``live_branches`` from ``gh pr list`` as a "defense-in-depth tombstone
— not load-bearing for correctness."  But the edge case it protects
is real: a session row was deleted (operator hand-edited
``codex_sessions.json`` or a manual ``kanban delete``) but the PR is
still open on the fork.  Today's tick would rename that worktree into
``.deleted-<ts>/`` even though the operator may still want to merge
the PR.

The cost of fixing this is tiny: one ``gh pr list`` call per hourly
tick, ~50 LOC, and it slots into the existing ``broker.gc`` call
signature (``live_branches: set[str] | None``).

## Goal

After this ISA, ``CodexGcWatcher._tick`` calls
``gh pr list --state open --json headRefName --limit 200`` once per
tick, builds a ``set[str]`` of branch names, and passes it as
``live_branches`` to ``broker.gc``.  Any failure (gh missing /
timeout / non-zero exit / JSON parse / custom callable raising)
absorbs to an empty set and logs a warning — the gc + reap calls
still fire so the tick is never aborted by a transient gh failure.

## Out of Scope

- Bumping the gc tick cadence (still hourly).
- Caching the live_branches set across ticks (one gh call per hour
  is fine; staleness doesn't matter for orphan detection).
- Surfacing the count in pulse / dashboard.

## Constraints

- **Failure in gh must NOT abort the tick.**  The watcher's
  guarantees from P5.1 (gc and reap both run every tick, in
  isolated try/except) MUST hold even if the new lookup raises.
- **No `gh pr merge / close / edit / delete`.**  The watcher
  remains a pure observer (P3.5 ISC-13 spirit).
- **Argv list, no shell string.**  Subprocess call uses an argv
  list so no quoting concerns.

## Decisions

**D-1 (2026-05-25): one gh call per tick, no cache.**
At an hourly cadence the cost is negligible (one subprocess <5 s).
Caching adds invalidation complexity for no observable benefit.

**D-2 (2026-05-25): inject the gh callable for tests.**
Subprocess-in-tests is slow and non-deterministic.  The injection
seam follows the same pattern as `CodexMergeWatcher`'s
`gh_pr_view` injection.
